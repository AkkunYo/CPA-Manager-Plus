# Fork 面板发布

本 fork 使用 `.github/workflows/fork-release.yml` 的 **Fork Panel Release**，在 GitHub 上构建和上传 `management.html`。

1. 将 fork 定制内容压缩为一个提交，rebase 到目标上游版本并推送 `main`。
2. 在已核实的提交上创建新的 `v<上游版本>-cq.<序号>` 标签并推送，保留已有标签。
3. 在 Actions 中手动运行 **Fork Panel Release**，工作流分支选择 `main`，填写标签、标签对应的完整提交 SHA 和发布说明。
4. `publish=false` 只运行检查并保存构建附件；`publish=true` 在检查通过后上传、下载校验并发布为 Latest。

工作流不创建提交、不 merge、不改写标签。构建源码来自指定标签，发布流程来自此次运行的 `main` 提交，因此也能发布添加 CI 之前已经创建的标签。

检查包括前端测试、仓库级测试、Go 测试、Lint、类型检查、生产构建、Demo 隔离和图标资源。面板生产依赖审计必须无漏洞，全工作区审计阻止高危及严重漏洞；其他工作区的中低危告警仍显示在日志中，发布说明应记录已知问题。

发布任务只获得仓库内容写权限，使用 `GITHUB_TOKEN`，不需要额外上传密钥。已有草稿可续传缺失附件；已有附件的大小或 SHA256 不一致时停止，不覆盖附件。完整下载校验通过后才发布。已发布且内容完全一致的版本可幂等重跑。

此流程只分发前端面板。独立 Manager Server 需要另行编译部署。启用 fork 的 Actions 时，应保持继承的上游发布、通知、更新通道等工作流禁用；本流程仅手动触发。
